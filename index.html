01 / The work

Three projects, revisited.

Each one started as a course project. For the capstone, I picked apart what could be improved, changed the code, and tested the results.

01 / CS 465

Travlr

Software design and engineering

A full-stack travel application built with MongoDB, Express, Angular, and Node.js. I revisited the authentication flow and API endpoints, with a focus on making the application safer and easier to maintain.

The biggest changes were password hashing, JWT verification, protected write routes, and stronger request validation.

Work completed

02 / CS 360

Android Inventory

Algorithms and data structures

A Java and SQLite inventory app. The original version could store and manage items, but it was missing some basic ways to work with a growing list.

I added live search, sorting, and low-stock filtering, then tested them together. I also fixed input and account-creation issues.

Work completed
  • Search and sorting
  • Low-stock filtering
  • Input validation
  • Account flow fixes
03 / CS 340

Grazioso Salvare

Databases

A rescue-animal dashboard using Python, MongoDB, and Dash. I rebuilt the local environment, restored the data, and worked through the database and dashboard code.

The updated version removes credentials from source files, validates database operations, replaces fragile map field references, and runs on modern Dash. I tested it against 10,000 animal records.

Verified results
  • 10,000 animal records
  • 519 water rescue matches
  • 197 mountain rescue matches
  • 22 disaster rescue matches
02 / About

Why I chose this work

I've spent a lot of time on the hardware side of engineering. That experience has shaped how I think about software. It's one thing to get something running once. It's another to understand how it behaves, where it can fail, and how someone else will maintain it.

That's what I tried to focus on in these enhancements. I worked on security in the web application, usability and algorithms in the inventory app, and reliability in the database dashboard. They're different projects, but they all pushed me to be more deliberate about the decisions I make in code.

My goal is to move into a software engineering role where I can keep building that skill set, particularly in embedded or aerospace systems.
